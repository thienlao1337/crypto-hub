# Crypto Hub

Панель крипто-инвестора: портфель с Bybit и Binance в одном месте, рыночные
графики с индикаторами, технические сигналы, алерты и Telegram-бот-зеркало.

> **Это не финансовая рекомендация.** Сигналы и индикаторы — технический
> анализ на исторических данных. Автотрейдинг по умолчанию выключен и
> работает в режиме бумажных сделок, пока реальная торговля не включена
> отдельным подтверждением.

## Статус

Проект в разработке.

Готово: схема БД и миграции, вход с двухфакторной аутентификацией,
закрытая регистрация по приглашениям, подключение ключей Bybit и
Binance, синхронизация балансов и сделок, экран портфеля с оценкой,
распределением и графиком стоимости, раздел рынка со свечным графиком,
индикаторами, стаканом и лентой сделок в реальном времени, сравнение
бирж, сигналы с обоснованием и статистикой точности, алерты с доставкой
в панель и Telegram, Telegram-бот, фоновый процесс синхронизации.

Дальше по плану: виджеты дашборда, инструменты (конвертер и калькулятор
комиссий), автотрейдинг, прод-деплой.

## Стек

| Слой | Технология |
|---|---|
| Веб-панель | FastAPI + Jinja2, Alpine.js, TradingView Lightweight Charts |
| Бот | aiogram 3 |
| БД | PostgreSQL 17, SQLAlchemy 2.0 (async), Alembic |
| Биржи | ccxt (REST + WebSocket, sandbox для testnet) |
| Индикаторы | pandas / numpy, собственные реализации EMA, SMA, RSI, MACD, Bollinger |
| Фоновые задачи | APScheduler в отдельном процессе |
| Деплой | Docker + docker-compose |

Реалтайм сделан без Redis: высокочастотные потоки (стакан, лента сделок,
котировки) идут через мультиплексор WebSocket-подписок внутри веб-процесса —
одна подписка на биржу независимо от числа зрителей; редкие события
(сработавшие алерты и сигналы из фонового процесса) доставляются в браузер
через `LISTEN/NOTIFY` PostgreSQL. Отдельный брокер сообщений на текущем
профиле нагрузки был бы лишней движущейся частью.

## Запуск

Нужен Docker с плагином Compose.

```bash
cp .env.example .env
```

Заполнить в `.env` как минимум три значения:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"          # SESSION_SECRET
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"  # ENCRYPTION_KEY
```

и `SEED_OWNER_EMAIL` / `SEED_OWNER_PASSWORD` — это первый аккаунт владельца.
Остальные пользователи регистрируются по инвайту, который владелец выдаёт
из админки.

```bash
docker compose up -d --build
```

Панель поднимется на http://localhost:8000, проверка живости —
http://localhost:8000/healthz. Миграции применяются автоматически
отдельным сервисом `migrate` до старта веба, а `worker` в это же время
начинает опрашивать биржи.

Если порт 8000 на машине занят, поменяйте `WEB_PUBLIC_PORT` в `.env` —
внутри контейнера порт всегда 8000.

При запуске по обычному http (без сертификата) поставьте
`SESSION_SECURE_COOKIE=false`, иначе браузер не отправит сессионную
cookie и войти не получится.

Бот запускается только с `BOT_TOKEN` от [@BotFather](https://t.me/BotFather).
Без токена контейнер `bot` поднимается, пишет об этом в журнал и ничего
не делает — панель работает и без него. Указав токен, перезапустите:
`docker compose restart bot`.

Войдите под `SEED_OWNER_EMAIL` — это владелец панели. Остальные
пользователи регистрируются по приглашению: раздел «Приглашения»
доступен только владельцу, он выдаёт ссылку вида
`/register?code=...`. Код одноразовый, с настраиваемым сроком и
необязательной привязкой к конкретному адресу почты.

Остановить:

```bash
docker compose down
```

Полностью, вместе с данными базы:

```bash
docker compose down -v
```

## Разработка без Docker

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
```

Нужен работающий PostgreSQL; в `.env` указать `POSTGRES_HOST=localhost`.

```bash
alembic upgrade head
uvicorn app.web.main:app --reload
pytest -q
```

Тесты можно гонять и в контейнере — в том же окружении, что и рантайм,
без локального venv:

```bash
docker compose --profile test run --rm tests
```

## Ключи бирж и безопасность

API-ключи бирж хранятся в базе только в зашифрованном виде (Fernet, ключ
из `ENCRYPTION_KEY`), в логи и в шаблоны не попадают — в интерфейсе
показывается лишь маска. При добавлении ключа его права проверяются
запросом к бирже: торговля разрешается, только если её подтвердила сама
биржа, а не пользователь в форме.

Рекомендуемый режим — **ключи только на чтение**. Права на торговлю нужны
исключительно для автотрейдинга и включаются отдельным осознанным шагом.

Двухфакторная аутентификация включается в разделе «Безопасность». Она
включается только после того, как код из приложения подтверждён — так
нельзя запереть себя, отсканировав QR с ошибкой. Вместе с ней выдаются
десять одноразовых кодов восстановления; в базе от них остаются только
хеши, поэтому показываются они ровно один раз.

Подбор пароля ограничен: после десяти неудач подряд адрес временно
блокируется. Отсчёт ведётся от последнего удачного входа, чтобы давние
опечатки не накапливались и однажды не заперли хозяина аккаунта.

`ENCRYPTION_KEY` хранить отдельно от бэкапа базы: имея дамп без ключа,
ключи бирж расшифровать нельзя — в этом и смысл. Обратная сторона в том,
что при потере `ENCRYPTION_KEY` их придётся заводить заново.

## Telegram-бот

Зеркало веб-функций, работает через те же сервисы — цифры в чате и на
сайте не расходятся.

| Команда | Что делает |
|---|---|
| `/portfolio` | Сводка по балансам с разбивкой по биржам |
| `/price BTC` | Котировка на обеих биржах и разница между ними |
| `/signals` | Свежие сигналы по отслеживаемым парам |
| `/alert BTC > 70000` | Создать алерт по цене |
| `/alerts` | Список своих алертов |
| `/unlink` | Отвязать чат от аккаунта |

Чат привязывается кодом: он выдаётся в панели, в разделе «Безопасность»,
и отправляется боту одним сообщением. Код одноразовый и живёт 15 минут.

Доставка отделена от записи события: сработавший алерт попадает в ленту
панели сразу, а в чат уходит следующим проходом фонового процесса. Если
бот недоступен или пользователь его заблокировал, событие не теряется и
не задерживает движок алертов.

## Структура

```
app/
  config.py            настройки из окружения
  db.py                движок и сессии SQLAlchemy
  models/              ORM по доменам
  exchanges/           адаптеры Bybit и Binance поверх ccxt, мультиплексор WS
  providers/           CoinGecko, индекс страха и жадности
  services/            бизнес-логика, общая для веба и бота
  web/                 веб-панель: роутеры, шаблоны, статика
  admin/               админка владельца: пользователи, инвайты, справочники
  bot/                 Telegram-бот
  worker/              фоновые задачи (синхронизация, сигналы, алерты, доставка)
alembic/               миграции
docs/ARCHITECTURE.md   схема БД и архитектурные решения
tests/                 тесты сервисного слоя
```

## Отступления от типового стека

**bcrypt используется напрямую, без passlib.** passlib не выпускался с
2020 года и несовместим с bcrypt 4.1+, то есть тянул бы за собой заметно
устаревшую версию хеширования паролей. Для продукта, который хранит доступ
к биржевым аккаунтам, это неоправданный компромисс.
